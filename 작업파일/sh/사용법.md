# 소리 재생 + 동시 녹음 프로그램 사용법

`sound_io.py`는 실험용 소리를 스피커 A, B로 내면서 UMA-16 16채널 녹음을 함께 하는 프로그램이다. Windows와 Mac에서 같은 파일을 쓴다. 자동 수집 순서(장치 구상도 그림 8)의 ③ 재생과 ④ 녹음을 맡는다.

## 처음 한 번 준비

1. Python 3이 있어야 한다. 터미널(Windows는 PowerShell, Mac은 터미널)에서 `python --version`(Mac은 `python3 --version`)을 쳐서 버전이 나오는지 본다.
2. 필요한 도구를 설치한다. 팀장의 `작업파일/파이썬/README.md` 설치(가상환경 + `requirements.txt`)를 이미 했으면 건너뛴다. 그 가상환경을 켠(activate) 상태로 이 폴더에서 실행하면 된다.
   ```
   python -m pip install numpy sounddevice soundfile
   ```
   Mac에서는 `python` 대신 `python3`를 쓴다(아래도 같다).
3. 노트북 소리 설정을 끈다.
   - Windows: 설정 → 시스템 → 소리 → 출력 장치 → "오디오 향상" 끄기, "공간 음향" 끄기
   - Mac: 따로 할 것 없음
4. 마이크 권한을 허용한다.
   - Windows: 설정 → 개인 정보 및 보안 → 마이크 → "데스크톱 앱이 마이크에 액세스하도록 허용" 켜기
   - Mac: 처음 녹음할 때 "터미널이 마이크에 접근하려고 합니다"가 뜨면 허용한다. 놓쳤으면 시스템 설정 → 개인정보 보호 및 보안 → 마이크에서 터미널을 켠다.
5. 터미널에서 이 폴더로 이동한다.
   ```
   cd "프로젝트 폴더/작업파일/sh"
   ```

## 명령

| 하고 싶은 것 | 명령 |
|---|---|
| 장치 목록과 프로그램이 고른 장치 보기 | `python sound_io.py devices` |
| 스피커 A로 1 kHz 재생 | `python sound_io.py play exp1_tone_1k --speaker A` |
| 스피커 B만 재생 | `python sound_io.py play exp2_band_4k --speaker B` |
| 실험 2: A·B 동시 재생 | `python sound_io.py play exp2_band_4k --speaker AB` |
| 여러 파일을 1초 간격으로 차례로 | `python sound_io.py play exp1_tone_1k exp1_tone_2k exp1_tone_4k --gap 1` |
| Ctrl+C를 누를 때까지 반복 (실험 2에서 스피커를 하나씩 켜 각도 맞출 때) | `python sound_io.py play exp2_band_4k --speaker A --repeat 0` |
| 재생하면서 UMA-16으로 녹음 | `python sound_io.py rec exp3_white --speaker A` |
| UMA-16 없이 노트북 마이크로 녹음 시험 | `python sound_io.py rec exp3_white --mic default` |
| 동시 시작 자가 시험 | `python sound_io.py selftest` |
| 장치 없이 프로그램 검사 (소리 안 남) | `python test_sound_io.py` |

- 소리 이름은 `../신호/signals/`의 파일 이름에서 `.wav`를 뺀 것이다(예: `exp1_white`, `exp3_chirp`, `00_채널확인`).
- `--speaker A`는 왼쪽 채널(스피커 A)만, `B`는 오른쪽(스피커 B)만, `AB`는 파일 그대로 낸다. 실험 1·3의 파일은 A 전용이지만 `--speaker B`로 고르면 같은 소리가 B로 나간다.
- `--volume`은 0~1이고 기본은 0.3이다(팀장 `audio.py`와 같은 약속). 처음엔 앰프 볼륨을 최소로 두고 시작한다. 실험 중에는 앰프 볼륨과 `--volume`을 바꾸지 않는다.
- 장치를 직접 고르려면 `--out`(출력)과 `--mic`(입력)에 `devices` 목록의 번호나 이름 일부를 넣는다. 이 옵션은 명령 이름 앞에 쓴다. 예: `python sound_io.py --out 헤드폰 play exp1_tone_1k`

## 녹음이 어떻게 되는가

1. UMA-16 녹음을 먼저 시작한다.
2. 0.3초 뒤 소리를 낸다(`PRE_ROLL`).
3. 소리가 끝나고 0.5초 더 녹음한 뒤 멈춘다(`POST_ROLL`).

그래서 녹음 길이는 소리 길이 + 0.8초쯤이다(실험 3의 2초 소리 → 약 2.8초). 소리 앞뒤가 잘리지 않게 하려는 것이다.

`rec` 명령의 결과는 이 폴더의 `기록/`에 저장된다(GitHub에는 올라가지 않는다).
- wav: 16채널, 48 kHz, 16비트
- `rec_log.csv`: 녹음마다 한 줄. 시각, 소리, 스피커, 볼륨, 녹음 길이, 재생 시작 추정 시각(`play_offset_s`), 최대 크기(`peak`, 1이면 찌그러짐), 경고, 장치 이름

`play_offset_s`는 두 장치(이어폰 단자, UMA-16)의 시계로 계산한 추정값이다. 빔포밍은 16개 마이크 사이의 시간차만 쓰므로 이 값이 정확하지 않아도 된다. 소리가 녹음의 어디쯤 있는지 볼 때 참고한다.

## 수집 프로그램에서 쓰기 (팀장용)

`sound_io.py`는 파일 하나로 혼자 돈다. 수집 프로그램 폴더(예: `작업파일/파이썬/`)에 복사해 두고 불러 쓴다. 소리 파일 위치(`SIGNAL_DIR`)는 `../신호/signals`이므로 `작업파일/` 아래 폴더면 그대로 맞는다.

```python
import time
from sound_io import SoundIO
from turntable import Turntable

sio = SoundIO()                           # UMA-16과 기본 출력 장치를 한 번 찾는다
with Turntable(None) as t:
    t.enable(True); t.home()
    t.goto(-30)
    time.sleep(0.5)
    rec, info = sio.play_and_record("exp3_white", "A", volume=0.3)   # rec: int16 배열 (표본 수, 16)
    sio.save(rec, "data/train_A/A_00001.wav")
# info: dict (time, sound, speaker, volume, fs, channels, rec_s, sound_s, play_offset_s, peak, warnings, mic, out)

sio.play("exp2_band_4k", "B")             # 녹음 없이 재생만
```

팀장의 `step3_rotate_and_play.py`에서는 `audio.play(...)` 줄을 `sio.play_and_record(...)`와 `sio.save(...)`로 바꾸면 된다.

- `SoundIO(mic="default")`로 만들면 노트북 마이크로 시험할 수 있다.
- `play_and_record(..., pre_roll=0.3, post_roll=0.5)`로 앞뒤 여유를 바꿀 수 있다.
- 회전 → 대기 → `play_and_record` → 저장 순서로 부르면 된다. 드라이버를 끌지(`e0`)는 잡음 테스트 결과에 따라 수집 프로그램에서 정한다.
- 이 노트북(Windows)에서 재생 한 번에 스트림을 여닫는 시간이 약 1초 더 걸렸다. 그림 8의 "녹음 1개 약 3.5초"보다 길어질 수 있다. 수집 속도가 문제가 되면 스트림을 열어 둔 채 쓰도록 고친다.

## 확인 순서

1. `python test_sound_io.py` → "모두 통과"가 나와야 한다.
2. 이어폰을 꽂고 `python sound_io.py play 00_채널확인 --speaker AB` → 왼쪽 귀에 낮은 소리, 오른쪽 귀에 높은 소리.
3. `--speaker A`, `--speaker B`로 각각 한쪽 귀에서만 들리는지 본다.
4. 이어폰을 빼고 노트북 볼륨을 중간쯤으로 한 뒤 `python sound_io.py selftest` → "결과: 통과".
5. 배선이 끝나면 앰프 볼륨 최소에서 시작해 2·3번을 실제 스피커로 다시 한다. 1.5 m에서 또렷하고 찌그러지지 않는 볼륨을 찾아 테이프로 표시한다.
6. UMA-16을 꽂고 `python sound_io.py devices` → 입력(마이크)에 UMA16, 16채널이 보여야 한다.
7. `python sound_io.py rec exp1_tone_1k --speaker A` → `peak`가 0.05~0.9 사이면 좋다.

## 문제 해결

| 증상 | 해결 |
|---|---|
| `No module named 'sounddevice'` | `python -m pip install sounddevice` |
| UMA-16을 찾지 못함 | USB를 다시 꽂고 `devices` 목록에서 이름을 확인한다. 이름이 다르면 `--mic 이름일부`로 지정한다. |
| UMA-16이 16채널이 아니라 2채널로 보임 (Windows) | Windows 소리 제어판 → 녹음 → UMA16 → 속성 → 고급에서 형식을 16채널 48000 Hz로 둔다. 그래도 안 되면 miniDSP 홈페이지의 UMA-16 v2 Windows 드라이버를 설치한다. |
| "마이크에서 소리가 들어오지 않는다" | 마이크 권한(위 준비 4번), USB 연결을 확인한다. |
| 엉뚱한 장치로 소리가 나옴 | `devices`로 고른 출력 장치를 보고 `--out`으로 지정한다. 블루투스 이어폰이 연결되어 있으면 끊는다. |
| 녹음 중 경고(input overflow) | 다른 프로그램을 닫고 다시 한다. 노트북 충전기를 꽂는다. |
| selftest 실패 | 이어폰을 빼고 노트북 스피커로 한다. 노트북 볼륨을 올린다. |
