# 마이크 녹음으로 소리 방향에 점 찍기

첫 버전의 목표는 **녹음 파일을 읽고 → 소리 방향을 계산하고 → 그림에 점을 찍는 것**이다.
아두이노 연결이나 추가 패키지 설치 없이 Python 3.9 이상에서 실행한다.

## 처음 실행하기

1. VS Code 메뉴의 **터미널 → 새 터미널**을 연다. 현재 폴더는 이 프로젝트의 `newton-acoustic-camera`여야 한다.
2. 다음 명령을 입력한다.

   ```sh
   python3 작업파일/방향추정/locate_sound.py --demo
   ```

3. 왼쪽 탐색기에서 `작업파일 → 방향추정 → 결과 → 연습`을 연다. `direction.svg`가 결과 그림이다. Finder에서 이 파일을 브라우저로 열면 그림을 볼 수 있다.

예상 출력은 **가로 약 +20도, 세로 약 +10도**이다. 빨간 점은 녹음으로부터 계산한 방향이고, 초록 원은 가상 녹음을 만들 때 정한 정답이다. 두 점은 거의 겹친다.

`--demo`는 ‘실제 장비 없이 가상 녹음으로 연습’이라는 옵션이다. 결과는 실제 장비의 측정값이 아니다. 명령을 다시 실행하면 같은 연습 결과 파일을 갱신한다.

## 좌표가 뜻하는 것

- 원점 `(0°, 0°)`은 마이크 판의 정면이다.
- 가로 각도: 양수는 오른쪽, 음수는 왼쪽이다.
- 세로 각도: 양수는 위쪽, 음수는 아래쪽이다.
- 앞쪽에 소리가 있다고 가정한다. 이 첫 버전은 거리나 방 안의 미터 좌표를 구하지 않는다.
- 오른쪽·위쪽은 CSV에 정한 좌표계 기준이다. 실제 카메라의 좌우와 맞는지는 장비로 확인해야 한다.

## 생기는 파일

| 파일 | 역할 |
|---|---|
| `locate_sound.py` | 실행할 Python 코드 |
| `mic_positions_example.csv` | 구상도에서 옮긴 마이크 위치 예시. 실제 녹음 채널 순서는 미확인 |
| `결과/연습/demo_16ch.wav` | 프로그램이 만든 가상 16채널 녹음 |
| `결과/연습/direction.svg` | 계산 결과를 점으로 표시한 그림 |
| `결과/연습/direction.json` | 각도와 분석 조건을 숫자로 저장한 파일 |
| `test_locate_sound.py` | 계산과 파일 읽기가 예상대로 동작하는지 확인하는 코드 |

결과 폴더는 GitHub에 올릴 파일에서 제외했다.

## 코드의 흐름

1. `make_demo`: 각 마이크에 도착하는 시간이 서로 다른 가상 소리를 만든다. 실제 녹음에서는 이 단계를 건너뛴다.
2. `read_recording`: 녹음에서 최대 0.12초를 읽어 마이크별 숫자 목록으로 나눈다.
3. `find_delay`: 두 마이크의 녹음을 조금씩 밀어 보며 가장 잘 겹치는 시간차를 찾는다. 각 쌍에서 최대 2048개 샘플을 비교한다.
4. `estimate_direction`: 마이크 위치와 시간차에 가장 잘 맞는 방향 하나를 계산한다.
5. `save_plot`: 방향을 그림에 점으로 표시한다. 데모의 정답은 계산 함수에 전달하지 않는다.

계산은 **일반 상호상관으로 구한 도착 시간차 + 평면파 근사**를 쓰는 연습용 구현이다. GCC-PHAT, 지연-합 빔포밍, 딥러닝의 완성본은 아니다.
원리 참고: [MathWorks의 도착 시간차 설명](https://www.mathworks.com/help/fusion/ug/object-tracking-using-time-difference-of-arrival.html).

## 실제 녹음을 받으면

동시에 녹음한 다채널 WAV와 각 채널에 해당하는 마이크의 위치가 필요하다. 먼저 팀에서 녹음 형식과 **몇 번째 채널이 어느 마이크인지**를 확인해야 한다. 예시 CSV의 순서를 그대로 믿고 사용하면 안 된다.

실제 좌표 파일을 준비한 뒤 아래처럼 실행한다. 경로는 예시이므로 실제 파일 경로로 바꾼다.

```sh
python3 작업파일/방향추정/locate_sound.py --wav "녹음.wav" --positions "실제_마이크좌표.csv"
```

녹음 앞부분이 무음이면 `--start 2`처럼 소리가 나는 시작 시점(초)을 지정한다. 음속은 기본 343m/s이며, 필요하면 `--speed`로 기온에 맞는 값을 지정한다. 결과는 `결과/실제녹음/`에 저장되며, 다음 실행 때 갱신된다.

지원 형식: 일반 RIFF WAV의 PCM 16/24/32비트, float32, 해당 WAV_FORMAT_EXTENSIBLE. RF64·압축 WAV·MP3는 지원하지 않는다.
마이크는 같은 평면에 있고 한 직선에만 놓여 있지 않아야 한다. 채널 수와 좌표 개수가 같아야 한다.
기존 `신호/signals`의 WAV는 **스피커로 재생할 2채널 소리**여서 마이크 녹음 대신 입력할 수 없다.

## 아직 검증하지 않은 것

실제 UMA-16 녹음, 교실 반사음, 여러 음원, 실시간 녹음, 카메라 합성은 검증하지 않았다. 한 음원이 충분히 멀리 있는 조건을 가정한다. 특히 순음은 시간차 후보가 여러 개 생길 수 있어 이 첫 구현으로 실험 1의 정확도를 평가하면 안 된다. 먼저 여러 주파수가 섞인 소리로 실물 검증해야 한다.

그림의 점은 정확도나 신뢰도를 보증하지 않는다. 무음이나 명백한 입력 오류는 거절하지만, 반사음·채널 순서 오류가 그럴듯한 결과를 만들 수도 있다. `fit_error_samples`는 시간차들이 한 방향에 얼마나 잘 맞는지 나타내며, 정답과의 각도 오차나 확률은 아니다.

검증 코드는 프로젝트 폴더에서 다음 명령으로 실행한다.

```sh
python3 -m unittest discover -s 작업파일/방향추정 -p 'test_*.py'
```
