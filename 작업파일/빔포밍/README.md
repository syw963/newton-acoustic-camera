# 방향 계산: 지연-합 빔포밍

## 1. 지금 만드는 코드의 목적

**마이크 여러 개가 동시에 녹음한 소리를 읽고, 어느 방향에서 소리가 오는지 계산한다.**
그 결과를 각도, 방향별 그래프, 소리 지도로 저장한다.

**GitHub에서 바로 보는 실행 결과 (가상 녹음)**

- [단일 음원 결과 그림](예시결과/단일음원/direction.png) · [각도 요약 표](예시결과/단일음원/summary.csv) · [방향별 그래프 데이터](예시결과/단일음원/direction_curve.csv)
- [두 음원 결과 그림](예시결과/두음원/direction.png) · [각도 요약 표](예시결과/두음원/summary.csv) · [방향별 그래프 데이터](예시결과/두음원/direction_curve.csv)

두 예시는 실물 측정이 아닌 가상 16채널 녹음의 계산 결과이다. 단일 음원은 (+20°, +10°), 두 음원은 (−30°, 0°)와 (+30°, 0°)에서 오는 소리로 만들었다.
두 음원 결과의 요약 표에는 가장 강한 한 방향이 적히며, 두 방향의 분리는 그림과 전체 그래프에서 확인한다.

예를 들어 스피커가 오른쪽 20°에 있을 때, 녹음을 분석해서 그 근처 방향을 찾는 것이 목표이다.
처음에는 가상 녹음으로 동작을 확인한다. UMA-16이 도착하면 같은 계산 함수에 실제 녹음을 넣어 비교한다.

이 단계의 입력과 출력은 다음과 같다.

| 구분 | 필요한 것 / 만들어지는 것 |
|---|---|
| 입력 1 | 동기화된 마이크 녹음 WAV: 시간 순서의 숫자 × 마이크 수 |
| 입력 2 | 각 녹음 채널에 해당하는 마이크의 위치 CSV, 단위 m |
| 입력 3 | 분석할 주파수 범위와 기온 |
| 출력 1 | 가장 강한 방향의 가로·세로 각도 |
| 출력 2 | 모든 후보 방향의 계산값과 소리 지도 |
| 출력 3 | 정면 높이의 가로 방향 그래프, 분석 조건 |

마이크 위치는 **이미 알고 있는 입력**이고, 소리 방향은 **알아내려는 출력**이다.
아두이노가 보내는 모터 각도는 나중에 정확도를 검사할 정답이며, 방향 계산 함수에는 주지 않는다.

## 2. 이번 단계의 범위

- 구현 방법: 계획서의 **지연-합 빔포밍**, 주파수 영역에서 계산한다.
- 먼저 녹음 파일 하나를 분석한다. 아두이노·스피커·마이크에 직접 명령을 보내거나 소리를 재생하지 않는다.
- 점 하나뿐 아니라 방향별 세기 전체를 저장한다. 두 음원을 켰을 때 봉우리가 두 개 생기는지 살펴볼 기반이다.
- 실시간 녹음, 카메라 영상 합성, 자동 수집, 딥러닝, 자동 음원 개수 판정은 다음 단계의 일이다.
- `작업파일/방향추정/`의 일반 상호상관 연습 프로그램과 별도이다. 이번 계산을 이어서 개발한다.

## 3. 원리를 한 번에 하나씩

1. 오른쪽에서 온 소리는 마이크 위치에 따라 도착 시간이 조금씩 다르다.
2. 프로그램은 ‘정면에서 왔다면? 오른쪽 2°라면? 오른쪽 4°라면?’을 차례로 가정한다.
3. 각 가정에 맞춰 16개 녹음의 시간차를 보정하고 더한다.
4. 실제 방향과 잘 맞는 가정에서 소리가 잘 겹쳐 합의 세기가 커진다.
5. 그 세기가 가장 큰 방향에 점을 표시한다.

코드는 시간차를 세밀하게 보정하기 위해 FFT를 쓴다. FFT는 녹음을 주파수별 성분으로 바꾸는 계산이다.
처음에는 공식을 외우기보다 **여러 방향을 시험하고 가장 잘 겹치는 방향을 찾는다**는 흐름을 이해하면 된다.

## 4. 좌표와 단위 약속

- 마이크 판 중심을 기준으로 x는 오른쪽, y는 위쪽, z는 앞쪽이다. 장비·카메라 기준의 좌우 일치는 실측으로 확인한다.
- 가로 각도 0°, 세로 각도 0°는 정면이다. 가로 +는 오른쪽, 세로 +는 위쪽이다.
- 가로 계산 범위는 계획서대로 −90°~+90°이다. 세로는 이번 단계에서 −40°~+40°로 둔다.
- 기본 간격은 2°이다. 이것은 탐색 간격이며, 실제 측정 오차가 2° 이하라는 보증은 아니다.
- 앞쪽 음원을 가정한다. 같은 평면의 마이크 도착 시간만으로 앞·뒤를 구분하지 않는다.
- 출력은 방향 각도이다. 음원까지의 거리나 방 안의 미터 좌표는 추정하지 않는다.
- 지도 색은 최대값을 0 dB로 둔 상대적인 세기이다. 측정한 소음도(dB SPL)나 정답 확률이 아니다.

`mic_positions_example.csv`는 구상도의 4×4, 42mm 격자 좌표를 옮긴 **예시**이다.
실제 UMA-16의 채널 순서를 확인한 파일이 아니다. 첫 열 `channel`은 0부터 시작한다.
예를 들어 channel=0은 녹음의 첫 번째 채널이다. 파일 행은 channel 번호순으로 읽는다.

구상도 좌표에서 최외곽 마이크 중심 사이 거리는 3×42=126mm이다.
기존 계획서의 근사식에는 D=4×42=168mm도 사용되므로, 이론 빔 폭과 비교할 때 D의 정의는 별도로 검토해야 한다.
이번 계산은 D 근사식을 쓰지 않고 각 마이크의 개별 좌표를 사용한다.

## 5. 처음 실행하기: Mac

프로젝트 폴더(`newton-acoustic-camera`)의 VS Code에서 **터미널 → 새 터미널**을 연다.
프로젝트 안의 `.venv`는 필요한 패키지를 설치하는 전용 Python 공간이다. GitHub에는 올리지 않는다.

첫 설치를 아직 하지 않은 컴퓨터에서는 아래 명령을 한 줄씩 실행한다.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r 작업파일/빔포밍/requirements.txt
```

설치를 끝낸 컴퓨터에서는 다음 명령만 실행한다.

```sh
.venv/bin/python 작업파일/빔포밍/main.py --demo
```

‘오른쪽 20°, 위쪽 10°’에서 오는 가상 녹음을 만들고, 그 WAV를 다시 읽어 계산한다.
기본 2° 간격에서 결과가 (20°, 10°) 근처에 나오는지 확인한다.
`작업파일/빔포밍/결과/` 아래에 실행마다 새 폴더가 생긴다. 이전 실행을 덮어쓰지 않는다.
`direction.png`는 지도와 가로 그래프, `result.json`은 각도와 조건, `power_map.npz`는 재분석용 계산값이다.
`summary.csv`는 계산한 각도 요약, `direction_curve.csv`는 정면 높이의 가로 그래프 데이터,
`power_map.csv`는 모든 가로·세로 방향의 계산값이다. CSV는 엑셀이나 Numbers에서 열 수 있다.
데모 실행에는 `demo.wav`, `demo_truth.json`도 생긴다. 정답 파일은 그림의 정답 표시와 오차 확인에만 사용한다.

Windows에서는 위의 실행 파일 `.venv/bin/python` 대신 `.venv\Scripts\python.exe`를 사용한다.

### 결과를 원하는 프로젝트 폴더에 저장하기

```sh
.venv/bin/python 작업파일/빔포밍/main.py --demo --output-dir 작업파일/빔포밍/결과/내첫결과
```

`--output-dir`는 저장할 **새 폴더**를 지정하는 옵션이다. 기존 폴더 이름을 지정하면 덮어쓰지 않고 멈춘다.
실제 WAV를 분석하는 명령에도 같은 옵션을 붙일 수 있다.

일반 실행의 `결과/`는 로컬 작업용이고 GitHub 업로드에서 제외된다.
선별해 공유하는 이번 예시는 `예시결과/단일음원/`, `예시결과/두음원/`에 넣었다.
여기에는 PNG·CSV·JSON·NPZ를 공유하며, 원본 가상 WAV는 Git에서 제외한다. 팀원은 `--demo`로 가상 녹음을 다시 만들 수 있다.
결과 JSON은 개인 컴퓨터의 절대 경로 대신 파일 이름을 저장한다.

## 6. 바꿔 보면서 이해하기

왼쪽·아래쪽의 소리를 시험하려면:

```sh
.venv/bin/python 작업파일/빔포밍/main.py --demo --azimuth -30 --elevation -10
```

가상 음원 두 개가 멀리 떨어진 예:

```sh
.venv/bin/python 작업파일/빔포밍/main.py --demo --two-sources
```

이때 독립적으로 만든 서로 다른 잡음을 사용한다. 두 봉우리가 나타나는지는 지도와 정면 높이 그래프로 확인한다.
가장 높은 점 하나를 출력한다고 해서 실제 음원이 하나라는 뜻은 아니다. 정확한 두 음원 분해능 판정은 후속 작업이다.

## 7. 실제 녹음으로 바꾸기

실제 채널 순서와 실측 위치를 확인한 CSV를 준비한 뒤 실행한다. 아래 파일 경로는 예시이다.

```sh
.venv/bin/python 작업파일/빔포밍/main.py --wav "녹음.wav" --mic-positions "실제좌표.csv" --temperature 22
```

실제 파일 모드에서는 `--mic-positions`가 필수이다. 예시 순서를 자동 적용하지 않는다.
WAV의 채널 수와 CSV의 마이크 수는 같아야 한다. 기존 `신호/signals` WAV는 스피커 재생용 2채널 파일이므로 입력으로 쓰지 않는다.
무음 구간은 `--start 2`처럼 건너뛸 수 있다. 기본적으로 그 시점부터 최대 3초를 분석하고, `--duration`으로 길이를 정한다.

기본 분석 대역은 500~4000Hz이다. 실험 1의 6·8kHz 순음 등은 해당 주파수가 포함되도록 범위를 바꿔야 한다.
4kHz 순음의 좁은 대역을 분석하는 예:

```sh
.venv/bin/python 작업파일/빔포밍/main.py --wav "녹음.wav" --mic-positions "실제좌표.csv" --fmin 3800 --fmax 4200
```

기온으로 음속 c=331.3+0.606T를 계산한다. 원본 채널의 상대 크기를 유지하고,
짧은 구간들에 Hann 창을 씌운 FFT를 평균한다. CSM의 대각항을 유지하는 기본 지연-합 방식이다.
정면 그래프는 **세로 0°에 대한 가로 절단면**이며, 회전 실험으로 얻는 실측 빔 패턴과 구분한다.

## 8. 파일을 읽는 순서

| 파일 | 역할 |
|---|---|
| `main.py` | 입력 → 계산 → 저장의 전체 흐름. 먼저 읽을 파일 |
| `beamforming.py` | 방향마다 시간차를 맞춰 더하고 소리 세기를 구하는 핵심 |
| `simulate.py` | 장비 없이 시험할 가상 마이크 녹음 생성 |
| `data_io.py` | WAV와 마이크 좌표 읽기 |
| `plot_result.py` | 계산 결과를 그림으로 표시 |
| `tests/test_beamforming.py` | 계산의 방향·크기·입력 처리를 확인 |

나중에 실시간 녹음을 붙일 때도 `beamform()` 계산 함수에 같은 형식의 숫자 배열을 전달한다.
딥러닝 비교에서도 같은 녹음·같은 좌표·같은 정답 각도를 공유한다.

## 9. 해석할 때 지킬 것

가상 데이터 통과는 실제 교실 정확도 검증과 다르다. 반사음, 채널 순서 오류, 동기화 문제, 마이크별 응답 차이,
큰 각도·고주파에서의 가짜 봉우리 때문에 결과가 틀릴 수 있다. 여러 후보가 있거나 그래프가 평평하면 최대점 하나를 정답처럼 해석하지 않는다.
순음도 계산할 수 있지만 한 주파수의 위상만으로 방향이 하나로 정해지지 않는 조건이 있다. 여러 비슷한 봉우리가 나타나는지 함께 본다.

이 프로그램은 한 녹음 안에서 음원이 움직이지 않는 조건으로 평균한 결과이다.
실험 1의 치우침·흩어짐, 실측 빔 폭과 0° 보정은 별도의 반복 측정과 분석이 필요하다.
실험 2의 최소 분리 각도와 실험 3의 학습·평가 전체를 이 프로그램이 끝낸 것은 아니다.

검증 명령:

```sh
.venv/bin/python -m unittest discover -s 작업파일/빔포밍/tests -v
```
